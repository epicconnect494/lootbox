# Threat model

| Threat | Mitigations | Residual risk / production notes |
|---|---|---|
| **RNG manipulation** (operator or insider biases results) | Server seed hash committed before use; user-controlled client seed; nonce bound; message locks pack version + manifest hash; rejection sampling; signed receipts; seed reveal + public verifier; test vectors. Battle seed committed before opponents join. | An insider with DB + key access could reveal seeds early to *predict* (not change) results for a specific user; mitigate with HSM/KMS for `DATA_ENCRYPTION_KEY`, restricted DB roles, and audit of decrypt calls. |
| **Seed leakage** | Seeds encrypted at rest (AES-256-GCM, AAD-bound); never logged (`log.ts` redacts seed/secret fields); revealed only via rotation/policy. | Use a KMS-backed envelope key in production; rotate `DATA_ENCRYPTION_KEY` with re-encryption job. |
| **Inventory double allocation** | `SELECT … FOR UPDATE` on version/outcomes/items; SERIALIZABLE transactions with retry; `CHECK` constraints on remaining quantities; partial unique index on active holdings; inventory guard trigger; conditional `UPDATE … WHERE quantity_remaining > 0`. Tested with 12 concurrent openers on 3 slots. | — |
| **Ledger imbalance** | Deferred balance trigger; append-only triggers; non-negative user balance check; materialized balance maintained by trigger; `reconcile` invariant job. | — |
| **Race manipulation** (self-refund loops, bonus abuse, bots) | Only qualified immutable events score; reversals for void/refund/chargeback; per-event cap; fraud review excludes users with open HIGH/CRITICAL risk events, suspended or bot accounts; lock snapshot hash; deterministic tie policy. | Add velocity/linked-account heuristics in the risk adapter. |
| **Raffle ticket tampering** | `raffle_entry` append-only; contiguous numbering under row lock; manifest hash published at close; draw bound to manifest hash and independent public randomness; redraw only appends with reason + audit. | Choose a public randomness source that is unpredictable at close time (e.g. a beacon pulse or block hash after close). |
| **Admin abuse** | Role/permission matrix tested for every role; separation of duties on pack approval; reasons required for pause/close/void/redraw/user changes; append-only audit with before/after hashes and correlation ids; address views audited; void policy restricted. | Add SSO + hardware MFA for admin roles; alert on audit anomalies. |
| **Account takeover** | scrypt password hashing; random session tokens stored hashed; `HttpOnly`/`SameSite=Lax`/`Secure` cookies; session revocation on exclusion/suspension; login rate limit + risk events for failures. | Add MFA, device fingerprinting via the geo/risk adapters, password breach checks. |
| **CSRF** | Double-submit CSRF secret tied to the session, required on all mutating routes. | — |
| **Botting / automation** | Rate limits per IP and per user; idempotency keys; risk events; battles bots disabled unless legally enabled and always labeled. | Add CAPTCHA / device attestation adapters. |
| **Chargebacks** | Chargeback recording debits the user, records HIGH risk event, excludes race points; unrecovered loss booked to a system account. | Integrate processor webhooks. |
| **Replay attacks** | `Idempotency-Key` with request-hash check (mismatch → 422); domain-level idempotency keys; nonce increments; concurrent duplicate retries block on the key row and replay. | — |
| **Odds personalisation** (regulatory) | Odds derive only from the manifest's remaining quantities; no user/deposit/VIP inputs exist in the draw path (`openPackInTx`). Live odds are shown from the same numbers. | — |
| **Deceptive presentation** | Reel strip built from disclosed quantities; winner at fixed slot; no near-miss logic; result shown before animation is optional (skip). | — |
| **PII exposure** | Addresses and KYC payloads encrypted; logs redact PII keys; IPs/UAs stored as keyed hashes. | Add field-level access controls in the admin UI and data retention jobs. |
| **Jurisdiction / legal** | Every paid mechanic is gated by per-jurisdiction flags defaulting to off plus global feature flags; nothing claims legal approval. | Legal review per market before enabling flags. |
